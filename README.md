# MarkTalk GUI · 用户使用说明

> 本文由三份用户说明（双引擎版、便携版、基础使用说明）**合并去重**而成，面向普通用户，不含实现细节。
> 文中路径一律写成**通用写法**（如 `<程序所在目录>\`、`<你的 llama.cpp 目录>\models`），请按你自己的实际位置替换。

## 一、这是什么软件

**MarkTalk GUI** 是一个**本地优先**的 AI 对话客户端，专门解决"聊久了上下文就满"的问题。
本地模型上下文通常只有 8K，聊一会儿就得清空重来。本程序的做法是：

- 对话记录以 **Markdown 明文**存在你自己电脑上；
- 上下文快满时，**自动把旧对话提炼成摘要**写进"记忆文件"；
- 然后清空对话、带着摘要继续聊。

于是**不再受上下文长度限制，可以一直聊下去，旧内容也不会丢**。
有一点要清楚：**它只是界面 + 记忆管理，本身不含模型、不会推理** —— 真正的推理由本地引擎（llama.cpp / FreeToken）或你配置的云端 API 完成。

- **平台**：仅 **Windows 64 位**。32 位 Windows、Linux、macOS 都不支持；ARM 版 Windows 需依赖系统的 x64 模拟层。
- **名称说明**：本项目的打包产物统一命名为 **`MarkTalk_GUI.exe`**。`2026-10-07` 及更早的便携包可能仍是旧名 `长对话管理器.exe` —— **同一个程序，功能完全相同**，以包内实际文件名为准。

## 二、能干什么（功能一览）

- **图形界面**：支持**拖拽文件 / 图片**，可按图片、按文件让模型分析；消息支持复制 / 编辑 / 重新生成 / 删除。
- **多引擎 + 自动发现引擎**：内置 `llama.cpp`（默认 **8080**）与 `FreeToken`（默认 **8000**）适配器；程序用 `netstat` **动态发现本机所有正在监听的端口**，**不依赖任何固定端口表**，谁活着用谁。
- **会话即文件**：一个 `.md` 文件 = 一个会话，随时切换、重命名、清空、删除；图片存在同级的 `_images\`。
- **两套归档语义**：**自动归档**＝旧对话提炼成摘要写进长期记忆；**右键「归档」**＝把整个会话隐藏，之后可在「本地用户 → 归档库」按年 / 月 / 日翻看。
- **云端 API（可选）**：能连 **OpenAI 兼容**的云端服务（DeepSeek、Qwen 云端等）；本地 / 云端只改 `engine` 一个字段就能来回切，状态栏显示 `☁ 云端` 提醒。
- **记忆分级**：公开内容与私密内容分目录存放，**云端模式下根本不加载私密目录**。
- **本地控制接口**：脚本、curl、AI agent 可直接操控程序，不用模拟点界面。
- **全程离线**：默认只连 `127.0.0.1`，不联网、无遥测（**除非你主动配置云端 API**）。
- **附带终端版**：`长对话-终端版.bat`，在黑窗口里打字聊天（只连本地引擎）。

## 三、首次使用：三步跑起来

1. **准备一个本地引擎**（推荐 [llama.cpp](https://github.com/ggml-org/llama.cpp)）：准备好服务程序与模型文件。
2. **启动引擎**：自行启动你准备好的本地引擎（推荐 [llama.cpp](https://github.com/ggml-org/llama.cpp) 的 `llama-server`）。起好后本程序会自动发现（用 netstat 扫监听端口），不需要固定端口、不需要双击特定脚本。
3. **启动界面**：双击 **`MarkTalk_GUI.exe`**，右下角显示"● 运行中"就能开始聊。

> **顺序反了也没关系**：先开界面、后开服务也行。程序**每 5 秒自动重试**，想立刻连上就点标题栏右侧的 **`⟳ 刷新`**。
> 服务没起来时界面也**不会一片空白** —— 程序启动时会先把本地记忆文件与会话内容加载好（这部分不需要服务）。

**停止引擎**：双击 `停止引擎.bat`。它只结束本程序启动的引擎进程，不会误杀其它程序。

**其它常用脚本**：`长对话GUI.bat`（从源码启动界面）、`长对话-终端版.bat`（终端版）、`设置云端密钥.bat`（管理云端 API Key）、`打包exe.bat`（重新打包）。

**端口**：llama.cpp 默认 **8080**，FreeToken 默认 **8000**，但**都可以随意改**。程序用 `netstat` **动态发现本机所有正在监听的端口**，所以引擎起在 8081、9999 还是 50000 都能被找到 —— **不依赖固定端口表**。

**配置**（可选）：把 `config.example.json` **复制一份改名为 `config.json`**，按需填你自己的路径。不填也能跑：llama.cpp 的模型路径是启动时从服务端探测的，只有 FreeToken 必须填模型目录。

### 程序目录里大概有什么

```
<程序所在目录>\
├── MarkTalk_GUI.exe              ← 双击运行（界面主程序）
├── 长对话GUI.bat                 ← 从源码启动界面
├── 长对话-终端版.bat             ← 终端版
├── 停止引擎.bat                  ← 停止引擎

```

## 四、双引擎与"自动发现引擎"

程序内置两套引擎适配器：**llama.cpp**（默认 `http://127.0.0.1:8080`）与 **FreeToken**（默认 `http://127.0.0.1:8000`，启动时会列出模型让你选）。
配置的端口上没有服务时，程序会**动态发现**本机正在监听的端口：先用 `netstat` 找出**所有** LISTENING 的回环 / 通配端口，再并上一份常见端口清单（Ollama 11434 / LM Studio 1234 / vLLM 8000 / text-gen-webui 5000 / TabbyAPI 5000 …）作兜底，然后并发探测每个端口是不是 OpenAI 兼容服务 —— **谁的端口号都行，不需要你手填**。

### 引擎怎么选

`config.json` 里的 `"engine"` 字段：

| 值 | 行为 |
|---|---|
| `auto`（默认） | 谁活着用谁；**两个都活着**时用「上次选的」，没有记录才弹窗问你 |
| `llama` | 强制用 llama.cpp |
| `freetoken` | 强制用 FreeToken |
| `openai` | 强制走云端 API |

连上后状态栏会显示当前引擎，例如：`✅ llama.cpp http://127.0.0.1:8080 · 模型：Qwen 3.8 27B · 自动归档已开启`

### config.json 常用字段

| 字段 | 说明 | 不填会怎样 |
|---|---|---|
| `engine` | `auto` / `llama` / `freetoken` / `openai` | 默认 `auto` |
| `llama.base_url` | llama.cpp 服务地址 | 默认 `http://127.0.0.1:8080` |
| `llama.models_dir` | llama.cpp 的 **GGUF 模型目录**，仅用于扫描模型能力（是否支持思考 / 推理强度） | **可留空**：模型列表照常列出，能力显示"未知"，对话不受影响 |
| `freetoken.base_url` | FreeToken 服务地址 | 默认 `http://127.0.0.1:8000` |
| `freetoken.models_dir` | FreeToken 的 **HF 模型目录**（每个子目录需含 `config.json`） | 留空则模型列表为空 |
| `freetoken.ft_exe` | `ft.exe` 的完整路径 | 留空则切换模型时报"未配置" |
| `openai.base_url` | **云端地址**（程序会智能识别：结尾含 `/v1` 或 `/api/v3` 等版本段则只拼 `/chat/completions`，否则拼 `/v1/chat/completions`） | 留空 = 不使用云端 |
| `openai.api_key` | **不要手写在这里** —— 请用 `设置云端密钥.bat` 加密保存，此字段会被强制清空 | — |
| `openai.model` | 云端固定模型名。`/v1/models` 不可用的服务**必须填** | 空则尝试 `/v1/models` |
| `openai.ctx` | 云端上下文上限（token），填 0 = 自动探测 | 探测不到时用 8192 |

示例：`llama.models_dir` 建议写成 `<你的 llama.cpp 目录>\models`。


#### ★ `base_url` 路径规则（2026-10-10 更新）

程序会**智能识别**你的 `base_url` 是否已含版本段：

| `base_url` 填法 | 实际请求地址 | 说明 |
|---|---|---|
| `https://api.example.com` | `https://api.example.com/v1/chat/completions` | 根地址 → 自动拼 `/v1` ✓ |
| `https://api.example.com/v1` | `https://api.example.com/v1/chat/completions` | 已含 `/v1` → 不再拼 ✓ |
| `https://ark.cn-beijing.volces.com/api/v3` | `https://ark.cn-beijing.volces.com/api/v3/chat/completions` | 已含 `/api/v3` → 不再拼 ✓ |
| `https://api.example.com/` | `https://api.example.com/v1/chat/completions` | 尾斜杠自动去掉 ✓ |

**规则**：`base_url` 结尾是 `/v1`、`/v2`、`/api/v3` 等**版本段**时，程序只拼 `/chat/completions`；
否则照旧拼 `/v1/chat/completions`。

> 如果你的服务商路径不是 `/chat/completions` 这种形式（例如需要 `/completions` 或其他自定义路径），当前版本**还不支持**。

### 两个引擎的差异（界面已自动处理，你一般不用管）

| 项目 | llama.cpp | FreeToken |
|---|---|---|
| 存活探测 | `GET /health` | `GET /v1/models`（它没有 `/health`） |
| 模型列表 | `/v1/models` 的扩展字段 | 扫描模型目录下含 `config.json` 的子目录 |
| 加载模型 | 热加载，立刻生效 | **重启 `ft serve` 进程**，要等几分钟 |
| 上下文上限来源 | `/v1/models` 返回的 `n_ctx` | `config.json` 里的 `text_config.max_position_embeddings` |

> FreeToken 的上下文上限**嵌套**在 `config.json` 的 `text_config` 里（不在顶层）；程序会按 顶层 → `text_config` → `llm_config` → `language_config` → `decoder` 依次查找，所以不同版本的目录结构都能兼容。

## 五、接入云端 API（OpenAI 兼容）

除了本地引擎，也能连 **OpenAI 兼容**的云端服务，例如 DeepSeek、Qwen 云端等。

### 三步搞定（推荐直接在界面里配）

1. **填地址 + 粘贴密钥**：点 `选择模型` → 底部 **`☁ 云端 API 设置…`** → 填地址、粘贴 Key、点「保存并重连」✓（也可双击 `设置云端密钥.bat` → 选 `1` → 粘贴 API Key，**输入时不回显**）。
2. **填地址**：`config.json` 的 `openai.base_url` 填服务商给的地址，例如 `https://api.example.com`（程序会智能拼接，详见上方「路径规则」）。
3. **选引擎**：`engine` 填 `"openai"`；或留 `"auto"`（**配了地址 + 密钥时会优先走云端**）。

> 💡 **`base_url` 智能识别**：程序会自动判断是否需要拼 `/v1`。
> 结尾是 `/v1`、`/api/v3` 等版本段 → 只拼 `/chat/completions`；否则拼 `/v1/chat/completions`。
> 详见上方「`base_url` 路径规则」。

### 云端 ⇄ 本地来回切

只改 `config.json` 里的 `engine` 一个字段，重启即可：

| 想用 | `engine` 填 |
|---|---|
| 云端 API | `"openai"` |
| 本地 llama.cpp | `"llama"` |
| 本地 FreeToken | `"freetoken"` |
| 自动（云端配全就优先云端；否则探本地、再扫常见端口） | `"auto"` |

> 云端配置留着不影响本地使用 ✓ 切换时状态栏会跟着变（云端显示 `☁ 云端 OpenAI <地址>`）。

## 六、密钥安全（重要，必读）

**你的 API 密钥不会写进 `config.json`。**

| 问题 | 回答 |
|---|---|
| 密钥存哪？ | **`api_key.dat`**（与 config.json 同目录），**不在 config.json 里** |
| 怎么加密的？ | Windows 自带的 **DPAPI**（真加密，不是 base64 伪装） |
| 谁能解开？ | **只有你这台电脑上的你这个 Windows 账户**。换用户 / 换电脑 / 文件被拷走 = 解不开 |
| config.json 里能写 key 吗？ | 程序**不会把 key 写进 config.json**（保存时强制清空）；你若手写了明文，程序会用它，但会**提示你改用加密存储** |
| 会显示完整 key 吗？ | **不会**。界面和日志只显示掩码，如 `sk-a…1a2b` |
| 密钥会进 git 仓库吗？ | **不会**。`api_key.dat` 与 `config.json` 都不随程序发布 |

**管理密钥**：双击 `设置云端密钥.bat`，菜单里可以 `1` 设置 / `2` 删除 / `3` 查看文件位置。

## 七、记忆分级：敏感内容物理隔离

`memories\` 下面分成两级：

```
memories\
  ├── cloud\      ← 公开话题。云端引擎和本地引擎**都能**看到
  └── private\    ← 敏感内容。**只有本地引擎**能看到
```

| 引擎 | 能看到哪些 |
|---|---|
| **本地**（llama.cpp / FreeToken / 本机其它引擎） | `private\` **和** `cloud\` ✓ 都能看 |
| **云端**（openai 提供商） | **只有 `cloud\`** ✗ `private\` 连扫都不扫 |

**为什么这样做**：走云端 API 时，**拼进请求的记忆内容会发到厂商服务器**。所以把敏感的（真实路径、公司资料、个人事务）放 `private\`：切到云端时程序**根本不加载那个目录**，里面的内容**物理上不可能**进入请求体（连跨会话的归档检索也只在可见的那一级里搜）。

- 每一级内部结构完全一样（`_archived\` 手动归档 / `_arch_batches\` 自动归档原文 / `_images\` 图片）——**附属目录跟着会话走**。
- 新建对话时，落点就是**当前生效的那一级**：云端模式 → `cloud\`；本地模式 → `private\`。
- **终端版**只连本地引擎，所以两级都能看，但它**写入默认落在 `private\`**（安全优先）。

## 八、记忆文件长什么样

`memories\*.md` 是**纯文本，可以直接阅读和编辑**。图形版逐条记对话，终端版记归档摘要，两者写进同一批文件，用**来源标记**区分：

```markdown
> 2026-10-08 20:14 [软件]        ← [软件] = 图形界面写的
**Q：你好**
	（这一行以制表符开头 = 上一条的续行，用来原样保留换行和缩进）

> 2026-10-08 20:14 [软件]
A：你好！有什么我可以帮你的吗？

## 会话归档 2026-10-08 20:21 [终端]   ← [终端] = 终端版归档出来的摘要
1. 用户要求仅回复"收到"。
2. 系统准确回复"收到"。
---
```

- **`[软件]` / `[终端]`** 标出内容来源；老记录没有这个标记，一样能正常读取。
- **以制表符开头的行是续行**，解析时原样拼回 —— 所以正文里的 `## 标题`、`A：` 之类不会被误当成新消息。
- **`## 会话归档`** 开头的块就是"长期记忆"：它之前的对话已被摘要覆盖，重载时不再占上下文。
- 标记只影响显示，**不影响两个程序互相读取**：终端版和图形版可以交替使用同一个会话文件。

## 九、归档机制（自动归档 + 手动归档）

**自动归档**：上下文快满时，程序自动把旧对话**提炼成摘要**写进同一个 md 文件，然后只把摘要 + 最近的对话发给模型 —— 这样就能**无限续聊**。

- 界面上会显示 `— 正在自动提炼归档… —`；
- 归档**不会删除**你的聊天记录，往上翻仍能看到全部；
- 如果上下文真的超了，程序会自动丢弃最旧的几轮并提示你；
- 可以开启「开篇总纲」永久保留，并支持对旧事做检索回忆。

**手动归档**：在左侧会话列表上**右键 →「归档」**，会把整个会话**隐藏**起来（不是删除），之后可在「**本地用户 → 归档库**」里**按年 / 月 / 日**翻看。

| 切换模型 / 调推理强度 | 底部 `模型·推理`，点开选 |

> `⟳ 刷新` = **手动重扫**（重新连服务 + 重新读记忆文件列表）。它是"想立刻看到最新状态"的快捷手段，不是唯一手段 —— 程序本身每 5 秒会自动重试。

## 十一、添加图片和文件（附件）

两个入口，**效果完全一样**：**拖拽**（直接从资源管理器把文件拖进窗口任意位置，可一次多个）或点左下角**圆形 `+`**（按住 Ctrl / Shift 可多选）。
文件按类型自动分流：**图片**（png / jpg / webp / bmp / gif）作为图片附件让模型"看"；**文本 / 代码**（txt / md / py / json / csv / log 等 30+ 种）**内容会随消息一起发给模型分析**；其它类型跳过并提示。

> 单个文本文件上限 **200 KB**（超出会截断并注明），防止一次把上下文撑爆。

删除附件不用一个个点 ×：

| 操作 | 效果 |
|---|---|
| **直接点条目** | 只选它（底色变蓝） |
| **Ctrl + 点** / **Shift + 点** | 加选取消 / 从上次点击处**范围选择** |
| **按住左键拖动** | **涂抹式框选**，划过的都被选中 |
| **点空白处** | 取消全部选中 |
| **右键条目** | 直接删这一个 |
| **`全选` / `删除选中` / `清空全部`** | 一次选中全部 / 删掉所有选中的 / 一次清空 |

附件栏**横向排列、排满一行自动换行**；条目多了会出现滚动条，不会挤压输入框。没有附件时整块自动收起。

## 十二、关闭 / 最小化 / 彻底退出

| 你做了什么 | 结果 |
|---|---|
| 点窗口右上角 **✕** | **不退出**，窗口收进右下角托盘，程序继续后台运行 |
| 点 **最小化** | 同上，收进托盘 |
| **双击托盘图标** / 右键 →「显示主窗口」 | 把窗口叫回来 |
| **右键托盘图标 →「退出（完全关闭）」** | **真正结束程序** |

也就是说：**✕ 只是收起来，要彻底退出必须走托盘右键菜单。**
首次收进托盘时会弹气泡提示，告诉你程序还在后台；如果托盘不可用（极少见），✕ 会自动恢复成"直接退出"，不会让程序卡在后台叫不回来。
托盘图标是**蓝底白色对话气泡**，Windows 默认折叠进 `^` 溢出区，拖出来固定一下就能一直看到。

## 十三、本地控制接口（让脚本 / agent 操控程序）

程序启动后会在 **`http://127.0.0.1:8765`** 开一个**只绑本机**的小接口，脚本、curl、AI agent 都能用它指挥本程序（不用模拟点界面）。

**端口**可在 `config.json` 里改：

```json
"control": { "enabled": true, "port": 8765 }
```

**token**：首次启动自动生成，用 **Windows DPAPI 加密**存进 **`control_token.dat`** —— 它是加密文件，用 `type` 读出来是乱码，正确做法是在「**设置 → 通用**」里查看并点「**复制控制 token**」。

```bash
TOKEN=<在「设置 → 通用」里点「复制控制 token」得到的口令>
curl -H "X-MarkTalk-Token: $TOKEN" http://127.0.0.1:8765/status
curl -H "X-MarkTalk-Token: $TOKEN" http://127.0.0.1:8765/chats
curl -H "X-MarkTalk-Token: $TOKEN" -H "Content-Type: application/json" \
     -d '{"text":"你好"}' http://127.0.0.1:8765/send
```

| 端点 | 方法 | 作用 |
|---|---|---|
| `/status` | GET | 引擎 / 模型 / 当前会话 / 是否在生成 / **记忆分级** |
| `/chats` | GET | 列出**当前可见**的会话 |
| `/chat` | GET | 读当前会话全文（`?name=xxx.md` 可读别的） |
| `/send` | POST | 发消息 —— **默认非阻塞**，返回 `task_id`，结果看 `/chat` |
| `/switch` | POST | `{"engine":"llama\|freetoken\|openai\|auto\|local"}` / `{"chat":"x.md"}` / `{"model":"..."}` |
| `/stop` | POST | 中断生成（流式可中断；摘要类请求不响应） |

**安全有三道锁**：

1. **只绑 `127.0.0.1`** —— 外网、局域网**都进不来** ✓
2. **每个请求必须带 `X-MarkTalk-Token`** —— 没有或不对 → `401` ✓
3. **带网页 `Origin` 的请求直接拒绝** → `403` ✓（防止"你浏览器里打开的某个网页"偷偷调你的本机接口 —— localhost 服务的经典坑）

> ⚠️ **`control_token.dat` 不要发给别人**，它等价于操控本程序的口令。

## 十四、数据放在哪 / 换电脑 / 搬家

`MarkTalk_GUI.exe` 是**自包含**的单文件程序（打包进了 Python 解释器、Tcl/Tk 界面库、VC++ 运行库、Pillow、pystray），**放在哪个目录都能跑**，目标电脑不用装 Python，也不用装 VC++ 运行库。
（把程序放进 llama.cpp 目录里只是**一种可选的部署方式**，不是必须。）

用户数据**都生成在 exe 所在的目录**：

```
<程序所在目录>\
├── MarkTalk_GUI.exe      ← 程序（自包含，放哪都行）
├── memories\             ← 聊天记录（一个 md = 一个独立会话）+ _images\ 图片
├── gui_settings.json     ← 记住上次选择的模型
├── config.json           ← 你的引擎配置
├── api_key.dat           ← 云端密钥（DPAPI 加密）
├── control_token.dat     ← 控制接口口令（DPAPI 加密）
└── logs\                 ← 运行日志
```

所以：

- ✅ **程序要和 `memories\` 在一起**；只把 exe 拷到别处会看不到聊天记录（程序会自动建一个空 `memories\`，于是记录是空的）。
- ✅ **整体搬家**：把 `MarkTalk_GUI.exe` + `memories\` + `gui_settings.json`（以及 `config.json` / `api_key.dat`，如果你配过）一起拷走即可。
- ✅ **指定别的数据目录**（也可做成快捷方式，在"目标"里加上这个参数）：`MarkTalk_GUI.exe --data-dir "<任意数据目录>"`

### 能换电脑用吗？

**能**，但有两个硬条件：

1. **那台电脑上必须跑着 llama-server**（或其它兼容引擎）。本程序只是界面客户端，**自己不含模型、不会推理**；没有服务时程序能打开，但会一直显示"连不上 llama-server"，什么也干不了。
2. **`memories\` 要放在程序旁边**。数据是"跟着文件夹走"的：只拷程序过去，历史记录不会跟过去。

```
目标电脑上需要有：
├── llama.cpp（含 llama-server.exe、models\、启动脚本等）
│      └─ 自行启动 llama-server 等兼容引擎
├── MarkTalk_GUI.exe          ← 本程序，放哪都行
├── memories\                 ← 想要历史记录就一起拷过去
└── gui_settings.json         ← 可选（记住上次选的模型）
```

**不支持的平台**：只能跑 **Windows 64 位**；32 位 Windows、Linux、macOS 都不行。

## 十五、便携版说明（如果你拿到的是便携包）

便携包是**开箱即用**的整包，**自带 Python / Tk / VC++ 运行时**，目标电脑无需安装任何东西，全程本地运行、不联网。

| 项目 | 内容 |
|---|---|
| 名称 / 版本 | `llama.cpp-便携版`，版本 `2026-10-07` |
| 平台 | Windows x64 |
| 界面 | 界面主程序（单文件，Python + tkinter）。**包内可执行文件名以包内实际为准**；本项目打包产物统一命名为 `MarkTalk_GUI.exe`（`2026-10-07` 及更早的便携包可能仍是旧名 `长对话管理器.exe`，**功能完全相同**） |
| 后端 | `llama-server.exe`（llama.cpp 的 OpenAI 兼容 HTTP 服务），地址 `http://127.0.0.1:8080`，router 模式（多模型按需加载，同时只驻留 1 个） |
| 启动顺序 | ① 自行启动 llama-server 等兼容引擎 → ② 双击包内的界面程序（`MarkTalk_GUI.exe` 或旧名 `长对话管理器.exe`），程序自动发现引擎并连接 |

**包含**：llama.cpp 全套运行时、`models\` 里 4 个 GGUF 模型（合计约 16.31 GB，含视觉模型与 mmproj 投影文件）、界面主程序、**全新空的 `memories\`**。
**不包含**：任何聊天记录、任何聊天图片、源码、个人配置。

### 关于这个压缩包的干净程度

打包前后做了三轮检查，结论是**包里没有任何人的聊天记录，也没有任何密码或密钥**：

| 检查项 | 方法 | 结果 |
|---|---|---|
| 聊天记录 | 用 8 个特征串（会话文件里的独特长句、图片文件名），把 16.98 GB **逐条解压后按字节搜索** | **0 命中** |
| 密码 / 密钥 | 对文本条目用严格规则（AWS / OpenAI / HuggingFace / 私钥 / Bearer / 用户名路径…） | **0 命中** |
| 是否被篡改 | 包里每个二进制与源文件做 **SHA256 逐一比对** | **64/64 完全一致** |

> 说明：如果拿粗糙的关键词（比如只搜 `sk-`、`AKIA`）去扫二进制文件，会得到上千个"命中" —— 那些是 DLL / 模型文件里的**随机字节**，以及服务程序自身鉴权代码里的正常字符串，**不是任何真实凭据**。

**数据位置**：所有用户数据都在**程序所在目录**（`memories\*.md` 一个文件一个会话、`memories\_images\` 图片按内容哈希命名、`gui_settings.json` 记住上次选的模型）。
想换成别的位置：`MarkTalk_GUI.exe --data-dir "<任意数据目录>"`；想整体搬家：程序与 `memories\` 一起拷走即可。

## 十七、常见问题

**Q：界面显示"连不上 llama-server"？** 请自行启动 llama-server 等兼容引擎。已经启动了的话，点一下标题栏右侧的 `⟳ 刷新`。

**Q：先开了程序、后启动服务怎么办？** 不用重启程序。程序会每 5 秒自动重试；服务起来后会自动连上，模型列表也会自动出现。想立刻连上就点 `⟳ 刷新`。

**Q：打开界面一片空白？** 点标题栏右侧的 `⟳ 刷新`。

**Q：提示"正在处理上一条，请稍候"？** 路由模式同一时刻只能跑一个模型请求，上一轮还在生成。等它结束，或点 `■` 停止。

**Q：提示"上下文超出模型上限"？** 程序会自动丢弃最旧的几轮保证能继续发出去。想彻底解决就新建一个会话，或把启动脚本里的 `--ctx-size` 调大。

**Q：我点了 ✕，程序怎么还在跑？** 这是有意设计的：✕ 只把窗口收进托盘，程序继续后台运行。要完全退出，请**右键托盘图标 →「退出（完全关闭）」**。

**Q：看不到托盘图标？** Windows 默认会把它折叠进 `^` 溢出区，拖出来固定到任务栏即可。

**Q：拖文件进窗口没反应？** 先确认拖的是图片或文本类文件（其它类型会被跳过，状态栏有提示）。若完全没反应，可能是拖拽库没加载 —— 改用左下角 `+` 按钮，效果一样。

**Q：能换电脑用吗？支持哪些系统？** 能换电脑，程序自包含；但目标电脑上也要有引擎并**先把服务跑起来**，想带记录就把 `memories\` 一起拷过去。系统**只支持 Windows 64 位**。

**Q：FreeToken 启动失败、报显存或内存错误？** FreeToken 需要 MoE 模型且显存 / 内存要够。22GB 级的模型大约需要 18.9GB 锁页内存，普通消费级配置（例如 8GB 显存 + 16GB 内存）会以 `cudaHostRegister: out of memory` 失败 —— 这取决于引擎和硬件，不是界面问题。内存小的机器建议保持默认的 `offload` 省内存策略，加内存后可改 `hybrid`（更快但更吃内存）。

## 十八、使用技巧

- **界面看着不对，先点 `⟳ 刷新`** —— 它等于"重连服务 + 重读记忆文件列表"，能解决绝大多数显示问题。
- **敏感对话就放 `private\`** —— 真实路径、公司资料、个人事务一律放这一级；即使以后切到云端，它也**物理上不可能**被发出去。
- **想全程离线**：把 `engine` 设成 `llama` 或 `freetoken`，并且不要在界面上配置云端地址。云端模式时状态栏会出现 `☁ 云端` 标记提醒你。
- **聊天记录就是 Markdown 文件**：可用任何编辑器打开、搜索、备份，也可以直接手写内容进去。
- **旧内容不会丢**：自动归档只是在原文里追加摘要块，往上翻仍能看到全部；被手动「归档」的会话去「本地用户 → 归档库」按年月日翻。
- **附件批量操作**：点 `全选` → `删除选中` 最快；也可以按住鼠标在附件上"涂抹"框选。
- **想让别的程序（脚本 / agent）操控本程序**：用 `127.0.0.1:8765` 控制接口 + 控制 token，比模拟点界面稳定得多。
- **换电脑前**：把 exe + `memories\` 一起拷贝，别忘了在新电脑上先把引擎服务跑起来。

## 十九、隐私与安全声明

- **本地引擎模式**：对话记录以 Markdown 明文存在本机 `memories\`，**不出本机、不联网、无遥测**（本地模式下 `private\` 和 `cloud\` 都能读，但怎么读都不会外泄）。
- **⚠️ 云端 API 模式**：**对话内容会发送到你填写的那个 API 服务商**，不再是纯本地。状态栏会显示 **`☁ 云端`** 标记提醒你当前处于云端模式。**想全程离线，请把 `engine` 设成 `llama` 或 `freetoken`。**
- **云端模式下 `private\` 根本不会加载**，里面的内容不可能进入请求体。
- **云端密钥**用 Windows DPAPI 加密存在 `api_key.dat`，绑定当前 Windows 用户 + 本机，界面与日志只显示掩码。
- **控制 token** 存在 `control_token.dat`（同样是 DPAPI 加密），等价于操控本程序的口令，**不要转发给别人**。
- 对话里的图片存在 `memories\_images\`（按内容哈希命名）；想整体搬家就把程序 + `memories\` 一起拷走，或用 `--data-dir "<任意数据目录>"` 指定别处。

## 二十、已知限制

- 仅支持 **Windows 64 位**；32 位 / Linux / macOS 不可用。
- **必须本机跑着推理引擎**（llama-server / FreeToken 等），否则界面能用但不能对话。
- 端口默认 **8080**（llama.cpp）/ **8000**（FreeToken），但**可以随意改**（含被占用后自动顺延的端口）。程序用 `netstat` **动态发现本机所有监听端口**，**不依赖固定端口表**，所以引擎起在 8081、9999、50000 都能被找到。
- 路由模式**同时只跑 1 个模型**；生成中再发消息会被挡下并提示。
- 上下文上限由模型决定；超出时自动归档或丢弃最旧几轮。
- `llama.models_dir` 只影响**能力扫描**（能不能识别"思考 / 推理强度"）；留空或路径不对时界面显示"未知"，**对话本身不受影响**。
- 云端 `base_url` **智能识别版本段**：结尾含 `/v1` 或 `/api/v3` 时自动调整拼接路径（详见「路径规则」）。自定义路径（非 `/chat/completions` 结尾）暂不支持。
- FreeToken 需要 MoE 模型且内存 / 显存充足（见"常见问题"）；另外不要同时开 FreeToken 桌面版和本程序指向**同一个模型目录**。
- 任何 OpenAI 兼容的服务程序（router 模式或普通模式）都能用；llama.cpp 的模型路径由服务端返回，**不需要在配置里填**。
